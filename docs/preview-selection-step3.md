# 预览与用户编辑：第三步——可信选区定位

日期：2026-10-07。前置页面与启动方式见 [第二步](preview-ui-step2.md) 及 [前端 README](../apps/web/README.md)。

## 已实现的流程

1. 用户在工作版本的 PDF 文字层中选择文字并保存反馈。原 `POST .../feedback` 仍只接收并返回 `received`，保存失败不启动定位，定位失败也不丢失已保存反馈。
2. 页面调用 `GET /api/tasks/{task_id}/versions/{version_id}/feedback/{feedback_id}/selection`。后端从该版本读取 PDF、DOCX 和预览身份，重新运行固定 PDF.js 6.4.299 提取声明页的文字层。逐项复核页、item 索引、UTF-16 起止偏移、选中文字、前后文及 PDF 哈希；客户端文字与偏移不直接成为锚点。
3. `.NET inspect-selection <docx>` 只读提取学术编辑器使用的同一组对象 ID 与字符文本。Python 结合正文故事、精确文字和可信 PDF 上下文匹配，生成绑定基础版本、DOCX/PDF 哈希及渲染器的 `selection-anchor/1.1`。API 不返回 XML 路径。
4. 普通单段唯一匹配返回 `ready`。重复文字不能消歧时返回 `ambiguous` 和候选位置、段落号及上下文，用「」标记候选命中的文字，同一段内的重复词也可区分；跨段、跨页或位于页眉页脚／注释的匹配即使唯一也先展示目标供确认。确认只决定位置，不扩大修改范围。
5. `POST .../selection/confirm` 接收 `selection-target-confirmation/1.0`，绑定反馈、版本、上下文、原定位结果与一个已展示候选。服务端重新读取来源后确认，记录追加式决定，并返回锚点。网络响应丢失时同一请求可幂等重试；新决定必须基于当前工作版本，历史版本只能读取已有决定。

## 可靠性边界

定位只允许已核验 PDF 换行与空白宽度造成的差异，不猜测大小写、标点、Unicode 兼容字符或连字。DOCX 范围保留源文件中的确切文字，字符偏移始终为 UTF-16；拆开代理对、伪造文字／上下文、越界 item、过期预览或组件漂移均被拒绝。前后文也核对内部空白，不能用去除单词间隔的结果强行消歧。

正文、页眉、页脚和不同脚注／尾注分别建立故事 ID，不跨故事拼接。字段及跨段字段、隐藏文字和隐藏样式、修订、绘图、公式、制表符及特殊连字符等不可靠结构不产生可执行锚点。表格条件样式可能隐藏文字时保守拒绝；即使存在安全的同文候选，也不静默忽略不安全候选。

界面仍一次显示一页，可选择当前页的单行、跨行和跨段文字。定位 API 可处理连续跨页提示，要求上一页选到末尾、下一页从开头开始；不连续、多段离散选择须分开提交。跨页界面手势尚未开放。

索引进程固定本地可执行文件、脚本、程序集及 PDF.js 资源指纹，设置处理时间、文件／索引大小、页数、候选和范围数量上限。超过限制返回需要补充或不支持，不截断候选后假称唯一。当前限制是开发阶段的保守资源边界，不是学校要求或产品性能承诺。

`selection_resolutions` 与 `selection_target_decisions` 追加存储于任务版本数据库。读取锚点会重新索引原 PDF/DOCX，验证来源与已确认选择；契约摘要只用于完整性和身份检查，不作为编辑许可。组件改变后须重启主机重新加载，无法重放的旧决定会要求重新定位。

界面展示正在定位、已定位、待选候选及失败说明；保存后自动展示定位结果，也可从反馈记录“查看位置”。切换版本中止旧请求并忽略迟到结果。确认期间禁用版本切换与新反馈提交，避免把正在确认的目标带到其他版本。

## 启动和后续接入

需要 Node.js 24、.NET 10、已安装的 `apps/web` 依赖和已构建的 `AutoFormat.DocxEditor`。`preview_host` 自动创建 `SelectionIndexes`；也可用 `--node`、`--selection-dll` 指定本地组件。缺少组件时预览与反馈接收仍可用，定位返回明确说明。程序嵌入时给 `create_local_api` 或 `bind_local_api` 传入 `selection_indexes`。

本步不启动完整 Brief 流水线、不调用模型、不改变 DOCX／报告／PDF，也不生成新论文版本。接下来第四步实现轻量自由文本解析、类型化属性和值、实际最小作用范围及范围澄清；第五、六步再衔接规则冲突与新版本编辑。可信锚点只能证明位置，不能证明用户已批准某项格式操作。

## 验证

定位测试使用真实 PDF.js 进程及 C# 学术对象 ID，覆盖来源重放、唯一／重复文字、可信上下文消歧、跨行 Unicode、连续跨页、多段目标确认、页眉确认、特殊结构拒绝、伪造和过期输入、并发确认、重启读取与响应丢失重试。浏览器检查保留第二步回归，并接入真实 LibreOffice 中文跨段选区的确认流程；重复候选使用独立的合成 PDF 夹具，未将它当作排版引擎一致性证据。

所有产物位于忽略的 `runtime/`、前端 `dist/` 与 .NET `bin/obj`。V0、历史版本和 `E:\Brief Parsing` 原项目均未修改。

最终检查：AutoFormat 全部回归 **140 passed / 5 skipped**；定位专项 **22 passed**；真实 LibreOffice 预览及独立歧义夹具的浏览器检查 **14 passed**。TypeScript 严格编译、Vite 构建、.NET 构建（零警告／错误）、契约 Schema 同步和 `git diff --check` 均通过。既有未配置显式环境的渲染检查仍跳过；真实渲染另由本轮浏览器检查覆盖。

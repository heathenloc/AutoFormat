# Brief Parsing：来源识别与漏提报告开发记录

日期：2026-10-02。对应本轮开发清单的第二项。

## 已实现

- 首先区分明确格式要求、示例、背景、模板观察、范围外内容与来源不明。
- 字数、词数、篇幅、页数、关键词／文献数量和具体内容要求不提取、不检查、不报漏提、不生成用户问题。
- 混合句按精确原文跨度拆分，保留字体、字号等格式部分；首行缩进“2字／2字符”仍属于格式。
- 模型调用前过滤，模型输出再次校验。示例及未确认的模板观察不成为执行规则。
- 按格式属性审计已有规则及待处理项，分别报告疑似漏提、不支持、已识别待定、来源不明和读取盲区。
- 报告保留原文、源文件及段／表／页位置，并接入初稿 V1 报告；不要求首次输入时逐项人工分类。
- 输出为 AcademicParseBundle 1.3；1.0–1.2 历史结果及原有解释仍可读取。

## 验证

| 检查 | 结果 |
| --- | --- |
| 复制版解析器回归 | 217 项通过；2 项 Linux 隔离测试在 Windows 跳过 |
| AutoFormat 应用集成回归 | 37 项通过；5 项外部引擎／预览环境测试跳过 |
| 复制来源快照 | 180 个来源文件；8 个已记录本地差异；无未记录差异 |

四项独立部署测试依赖复制时明确排除的 Docker／部署文件，沿用项目约定排除，未把它们算作通过。

7 份真实 Brief 均只读检查：6 份 DOCX 已生成诊断，1 份 `.doc` 因输入格式不支持被拒绝。原始文件哈希核对一致，既有人工标注草稿未覆盖。结果位于项目忽略目录 `runtime/brief_source_review_20261002/`。

这轮真实样本检查使用 fake provider，仅验证本地读取、确定性规则与来源审计，没有调用云端模型。现有真实样本仍有多种句式和属性无法形成安全的类型化规则；报告将这些格式线索暴露出来，不能据此宣布解析器已提取全部学校要求。

## 当前限制与后续工作

来源识别采用确定性词典及段落／章节边界，完整视觉区域判断、表格行列上下文、模板样式继承和 OCR 仍需后续开发。线索覆盖计数不是人工标注召回率；要衡量真实准确率，仍需要核对并确认真实 Brief 的标注。

解析器输出规则也不代表论文已经修改。当前 V1 发布链路仍是原稿副本基线；自动格式编辑的完成度另行验收。

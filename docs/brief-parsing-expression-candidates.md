# Brief Parsing：扩充表达识别与模型候选转换

> 日期：2026-10-04。真实 Brief 人工标注与准确率评测按用户要求暂缓。

## 本轮交付

论文入口现在输出 `AcademicParseBundle/1.6`，包含 `AcademicFormatRuleSet/1.5`、`AcademicSourceReview/1.2` 和未改变的模板观察契约 `TemplateLayoutReport/1.1`。个别规则仍使用 `AcademicFormatRule/1.1` 的完整作用范围和约束。决策快照契约保持 `AcademicDecisionSnapshot/1.0`，同时接收 Bundle 1.5 与 1.6。

`AcademicRequirementProjector` 已接入 `BriefParserService.parse_academic`。它将流水线保留的模型 Requirement 与原文独立证明逐项对照，符合要求的候选转成有来源 Requirement ID 的类型化规则，随后重新计算冲突与分片。程序直接识别的规则也保留，因此模型没有提取到某项时仍可输出可靠的原文规则。旧的 `AcademicFormatCompiler` 是正文对齐演示的兼容接口；论文正式入口使用新的投影器。

## 新增表达

| 类别 | 本轮覆盖的常见表达 |
| --- | --- |
| 对象 | 中英文正文、摘要、关键词、目录、参考文献、脚注／尾注、表题／图题、页码、页眉／页脚；摘要标题、目录标题、致谢、附录 |
| 标题 | 1–9 级；`Heading 5`、`Level 9 heading`、`第八级标题` 等；目录条目仍与正文标题分开 |
| 章节 | `Chapter 2 body text` 保留第二章限制；不扩大为全部正文 |
| 字体 | 字体属性中的明确英文名称、带引号名称及 SimSun／SimHei／KaiTi／FangSong 等受控别名；引号内名称不作关键词替换；不验证主机是否安装字体 |
| 字号／对齐 | `font size 12pt`、中文字号、`justified`、`centered`、`left-aligned` 等，与已支持的字号区间／上下界并存 |
| 字形／段落 | 肯定及明确否定的加粗、斜体；单／双倍行距、段前段后行数、常见英文缩进／间距名称；与下段同页、段中不分页、段前分页、文档网格 |
| 页面 | A3／A4／A5／Letter、纵向／横向、明确的组合侧边边距、装订线、页眉／页脚距离 |
| 页码／目录／题注 | 大小写罗马数字、阿拉伯数字、明确起始值、目录 1–9 级限制、表题／图题上下位置 |
| 说明章节 | 当最内层章节标题明确写“正文”等已注册对象，且证据索引保留同一章节的真实标题时，后续格式句可引用该标题补齐对象。保留标题和格式句两处证据；“章标题／节标题”的级别不自动猜测 |

以上为受控句式覆盖，不能解释为这些属性的一切自然语言写法均已支持。缺少单位的行距不假设为倍数；建议、多选、双重否定及未支持的比较表达维持待定。

## 候选校验

模型提示包含受信任的格式属性和对象注册表，并要求一属性一候选。提示不能替代以下程序校验：

通用模型候选仍沿用原来的 `CandidateValue`：`text`、`amount`、`range_end`、`items`。论文投影器补齐该结构到布尔、整数、区间和行距模式的归一，例如 `text="不加粗"` → `false`、`text="固定值20pt"` → `{mode: exact, amount: 20}`、`text="12-14pt"` → 字号区间；每个转换仍必须与原文独立证明一致。模型提示提供这种可实际提交的字段示例，不要求通用候选传递任意 JSON 对象。

1. 候选必须来自输入来源，引用精确证据，且来源已完整读取；示例、观察、背景或来源不明不能提升为学校明文要求。
2. 属性必须通过注册表映射；属性类型与语义键互相矛盾时拒绝。未知属性不映射到近似属性。
3. 候选对象及范围必须明确；不丢弃多对象或排除条件以获得可执行规则。
4. 值及单位通过类型验证。字号数值必须带 pt；物理长度允许确定换算，例如 25 mm → 2.5 cm；布尔值不能充当数值。
5. 同一证据必须能独立、唯一证明对象、属性、值、单位和约束。保留程序证明中的章节、字符、语言及提交条件；模型遗漏限制不会扩大作用范围。
6. 通过转换不等于可以立即编辑：条件仍待确认，区间仍只检查，冲突仍保留交集与余集，后续编辑器继续核对对象定位与能力。

`format_ruleset.candidate_reviews` 对每个保留的模型格式 Requirement 记录 `source_requirement_id`、状态、原因码、原文证据 ID、属性和规则链接：

- `accepted`：生成带该 Requirement 来源 ID 的规则；规则自身仍可能待条件或冲突确认。
- `covered`：重复候选已由同一规则覆盖。
- `pending`：值、范围、条件、证据验证或要求强度尚不能可靠转换。
- `rejected`：来源不适用、属性未注册／矛盾或类型不合法。

候选报告也进入解析 Markdown。错误模型候选不会覆盖独立证明的原文规则，也不会凭空创建用户需回答的格式值；真实原文缺口继续由来源审计和格式待处理项呈现。字数、词数、篇幅与内容要求在流水线和投影器两次过滤，不进入候选审计或问题队列。

单次最多验证 1024 个 Requirement；超过上限整体失败，不发布部分结果。规则范围组合仍遵守既有资源上限。

## 历史与扩展

Bundle 1.0–1.5 和既有 Schema 文件保持原语义。新增冻结版 `academic_semantic_extractor_v1_4`、`academic_source_policy_v1_1`、`academic_source_review_v1_1` 用于旧 Bundle 1.5 的重算；旧决策重放也选择原语义解析器。新版 Bundle 从 IR 重算规则、候选审计、来源审计及模板分组，篡改候选原因或规则值不能通过重读。

新增格式属性仍通过类型注册表、表达证明、候选映射和契约版本接入；不会把模型原话变成执行指令。本轮没有引入新的模型调用或外部依赖。

学术流水线指纹记录来源策略 1.2、规则投影器 1.5.0 及候选提示增量 1.0；通用领域指纹保持原行为。范围外过滤逐字段判断，不把 `A5` 和另一字段中的 `page` 拼成“5 pages”而误删合法纸张要求。

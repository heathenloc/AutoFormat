# 预览与用户编辑：第四步——轻量反馈解析与实际范围

日期：2026-10-07。承接 [第三步可信定位](preview-selection-step3.md)，启动方式见 [前端 README](../apps/web/README.md)。

## 用户流程

1. 在当前工作版本选择文字，选择“仅选中文字／所在整个段落／所有同类内容／全文”，输入格式反馈。
2. 保存前展示识别出的属性、值、类别、字符条件、实际最小修改单位及影响对象数。输入、范围或选区变化会取消旧预览并重新核对，只有绑定确切提交内容的预览返回后才能保存。页面切换与缩放清理选区后也重新核对。
3. 原反馈接收接口仍仅保存原话、原范围和选区提示，返回 `received`。页面随后读取独立的解析与定位结果；解析失败不会删除已保存的反馈。
4. 缺少具体值时展示结构化表单，可依次补齐多个条目。已理解的属性、值、角色、字符条件和原请求范围不能由补值答案改写。复杂条件、未知文字和范围不一致要求修改原话、重新保存，不能用表单绕过。
5. 重复或敏感目标先经第三步的位置确认。段落属性应用到整段，同类／全文及其他扩大范围另需确认实际范围；确认和补充只保存决定，当前不会执行格式修改。

例如：“这里居中”显示实际影响所在整段；“所有二级标题居中”与“仅选中文字”控件不一致时提示统一范围；选择“所有同类内容”后根据可信角色索引统计目标。“中文宋体”显示中文字符条件；若选中的文字不含中文，则保留为目标待核对。字体按字符条件过滤后的对象计数，不把数量当成字符数或页数。

## 解析能力与保守边界

`feedback_parser.py` 采用受控词典及完整消耗的句式解析，仅复用复制版解析库中的字体别名、冻结字号表、类型和范围校验器，不调用模型或完整 Brief 流水线。

- 支持常见字体、带明确单位的字号、中文字号、加粗／取消加粗、斜体、段落对齐、倍数／固定／最小行距、段前段后、首行／悬挂／左右缩进、分页相关开关、页面尺寸／方向／边距及表格边框。
- 支持明确对象类别和中文／拉丁字母／数字字符条件；同类范围可从已定位目标的唯一可靠角色补全。普通 Normal 样式不会凭猜测当成正文，不能分类时要求明确类别。
- 条件、排除项、区间、未知格式及互斥值会保留为澄清项，不选择其中一个值或丢弃限制。复杂表达应拆开提交。
- 咨询只记录问题，当前不生成答案或格式候选。内容润色、数量／篇幅、图片处理等要求不形成格式规则。
- “这里还是宋体”作为执行反馈处理，不将描述的现状当成新格式要求。只有内部适配器从所选版本规则快照重放得到已确认、无条件且适用的规则时才关联；独立预览主机没有该快照适配器时继续要求核对。带字符限制或其他无法证明适用的规则保守留待核对，不声称已验证实际格式。

`feedback_scope.py` 使用固定 C# 组件的 `inspect-selection` 和 `inspect-academic` 输出。段落、表格和分节都使用编辑器的真实对象 ID，客户端不能提供目标 ID 或 XML 路径。字体字符分类与编辑器的 Unicode 范围一致；局部范围使用可信锚点的确切文字，段落／同类／全文使用相应对象文本。

段落属性不能伪装成仅改几个字。页面设置目前只接受全文范围并列出实际分节；局部页面要求继续澄清。表格属性按整个表格核对。不可靠对象、超过资源上限、缺少索引或没有匹配目标均保持待定，不截断或静默丢弃。当前对象与条目上限是开发资源边界，不是学校要求。

## 接口和存储

所有接口沿用本地会话授权及版本来源检查：

| 接口 | 作用 |
| --- | --- |
| `POST /api/tasks/{task}/versions/{version}/feedback/review` | 接收原 `FeedbackSubmission/1.0`，返回 `FeedbackDraftReview/1.0`；不保存反馈、决定或论文文件 |
| `POST .../feedback` | 原接收入口保持 HTTP 202 与 `received`，不解析或编辑 |
| `GET .../feedback/{feedback}/analysis` | 重放原话、同版本定位及追加决定，返回 `FeedbackAnalysis/1.0` |
| `POST .../feedback/{feedback}/analysis/confirm` | 接收 `FeedbackConfirmationRequest/1.0` 的 `clarify_format` 或 `confirm_scope`；位置确认继续使用第三步专用入口 |

新增契约已同步到 `contracts/` 与 API Schema 目录。`FeedbackAnalysis` 包含现有 `FeedbackParseResult/1.0`、独立定位结果、已确认范围 ID 和决定数量，不等于有效规则快照。

解析结果存入 `feedback_parse_results`，答案存入 `feedback_processing_decisions`。原反馈及历史决定不覆盖；每次读取从原话和可信来源重新计算，校验来源哈希、结果哈希及决定链。确认绑定任务、版本、DOCX 哈希、上下文、反馈和原解析结果。新决定只接受当前工作版本；同一请求 ID 的确切重试返回已有结果，跨实例并发也只追加一次，不同答案复用请求 ID 被拒绝。其他并发修改要求重新加载。

页面使用内存中的会话和请求状态，解析结果绑定提交内容哈希；迟到、过期、错版本或错内容的结果被丢弃。确认期间禁用版本切换与提交；网络失败保留原答案和同一请求 ID。历史版本可以查看已保存的解析和决定，不能追加新确认。

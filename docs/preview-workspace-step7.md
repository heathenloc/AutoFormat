# 预览与用户编辑第七步：问题进度与历史分支

日期：2026-10-08。本步在第六步的反馈实际编辑之上，补齐已发布版本的工作区操作，不改写 V0、历史 DOCX、报告或 PDF。

## 1. 用户可以做什么

- 查看“反馈问题与进度”，按全部、待处理、已完成／记录筛选；展开所选文字，查看保存的原话及当前处理原因。反馈较多时每页最多 50 条，可以继续加载更早记录。
- 从启动器重新打开页面后，恢复待补充格式、待确认位置／范围、未决冲突及执行结果。点击“查看需求与位置”重新打开原有表单，沿用已保存的明确决定，不需要重复提交原话。
- 查看已完成反馈生成的版本；失败执行保留原执行请求身份，核对后重试同一操作。无需修改的反馈显示“格式已满足”，明确选择保留原规则的反馈显示“已保留原规则”。两者都不生成冗余论文版本。
- 展开报告待处理项，阅读要求原文、未处理原因、后续处理建议和来源证据。这是所选版本的历史事实，不会把未确认要求自动变成默认规则。
- 查看历史版本后，明确点击“从此版本继续修改”。仅浏览不改变工作起点；V0 保留为原稿，不提供此操作。从历史 V1 或后续版本产生的下一次实际修改创建独立子版本，已有后代保留。

页面在切换、确认和执行期间锁定相互冲突的写操作。工作进度刷新失败时，仍可查看已加载的论文和报告。会话令牌继续只保存在内存中，整页重开须由启动器重新授予会话。

## 2. 按来源恢复进度

新增 `FeedbackWorkQueue/1.0`。队列绑定任务、基础 DOCX 哈希、预览／规则上下文及当前规则快照；条目来自不可变反馈记录、原文件重新解析、位置及范围确认、规则决定和执行回执，不维护另一份可任意修改的“已完成”标记。

进度包括待确认位置、待补充格式、待确认范围、待解决冲突、待核对／生成、执行中、失败、已生成版本、格式已满足、已保留原规则、咨询、范围外、需进一步核对和依据校验失败。咨询与范围外请求仅为记录，不代表系统回答了咨询或修改了论文。

读取进度不执行编辑、不新增反馈或确认，也不主动把历史反馈加入当前规则核对头。已有定位缓存可能被重建。已完成条目的“查看需求与位置”只打开来源；不会因浏览旧需求而重新应用它。

分页使用服务端单调记录游标；插入新反馈不会改变后续旧记录页的边界。页面展示已加载记录的待处理数量，继续加载可看到更早反馈。

## 3. 继续历史版本与例外隔离

新增 `VersionContinuationRequest/1.0` 与 `VersionContinuation/1.0`。请求必须携带所选版本 ID／DOCX 哈希、预期当前工作起点及独立请求 ID，不能提交规则文本、文件路径或修改计划。

服务先校验所选版本的论文、预览、预览元数据、JSON／Markdown 报告并绑定已发布规则引用；已有规则核对头时按来源重放。随后在同一 SQLite 事务内核对当前工作起点及规则头、写入回执和切换指针。相同请求并发只完成一次；同 ID 不同内容拒绝。响应丢失后重试返回原回执与实际当前起点，不会把后来继续编辑的工作起点倒退回去。

分支必须从**所选已发布版本实际引用的规则**开始。某个 V1 的反馈核对头可能含有随后生成 V2 时才确认的例外，不能直接复用。历史切换因此追加 `restart` 事件及新的规则快照：重新采用所选版本的学术规则和已发布继承规则，清空当前轮输入／冲突选择。此前反馈、决定、快照及生成的版本仍完整保留，可以按来源重放。

`restart` 重放必须找到对应的继续编辑请求和校验通过的回执，普通快照及事件仍逐条验证。事务中规则头发生变化时，整次切换回滚。重复选择当前工作起点不重置正在处理的反馈。

例子：V1 → V2 新增 14pt 本处例外；回到 V1 后提交加粗，生成 V3，父版本为 V1，字号保持 V1 的 12pt；V2 的 DOCX、报告、PDF 字节不变。继续 V2 时则继承 V2 已发布的例外，第六步的后代规则重定位逻辑继续适用。

## 4. 本地 API

| 路由 | 作用 |
| --- | --- |
| `POST /api/tasks/{task}/versions/{version}/continue` | 校验历史版本并明确切换工作起点，保存幂等回执 |
| `GET /api/tasks/{task}/versions/{version}/work-items?before={cursor}` | 按来源恢复所选版本的反馈进度；游标可省略 |

继续沿用回环主机、同源检查和 `X-AutoFormat-Session` 鉴权。契约同步导出到 `contracts/` 及 API 的 schema 副本，不改变旧反馈、规则快照或版本节点契约。

## 5. 当前边界

报告中的首次被忽略学术要求目前提供明细及证据查看，尚不提供“发布后重新回答学术问题并应用”的界面。历史分支不能读取任务全局最新学术决定来替换所选版本依据，后续接入时需要独立、明确绑定父版本的决定／执行契约。已支持的后续格式微调继续通过预览反馈完成。

当前整轮快照 `ready` 校验保留：有任何待定或不支持片段时，独立可靠规则也暂不执行。未实现目录／页码缓存刷新等额外编辑能力。规则核对仍有每个基础版本 64 条输入、256 次修订等既有上限；历史重启追加一条修订，不删除旧历史以绕过上限。

本步不包含 Windows 安装包、WebView2 外壳或跨任务工作台。第八步继续整体集成与打包验收。

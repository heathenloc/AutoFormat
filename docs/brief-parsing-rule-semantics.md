# 第四项：完善规则语义

> 日期：2026-10-03。适用于 AutoFormat 内 `modules/brief_parsing` 的开发副本。

## 1. 已实现的能力

| 能力 | 当前行为 |
| --- | --- |
| 对象与局部范围 | 保留正文、各级标题、目录条目、表头／表内文字、脚注／尾注、页眉／页脚、表题、现有引用等角色；支持明确章号、表格序号、页码区域与排除范围；中文／英文摘要按对象语言分别限定，避免扩大成全文西文 |
| 字符范围 | 中文、西文字母、数字分别表示；“英文及数字”包含后两者。“中文字体宋体，字号小四”中的字号仍作用于原对象的全部字符 |
| 层级范围 | 表格整体字体与表头／表内字体相交；目录整体字体与各级目录条目相交；各级正文标题与目录条目保持区别 |
| 格式约束 | 保留单值、字号区间、字号上下界和禁用字体；小四至四号归一为 12–14 pt，区间和上下界不自动选值 |
| 段落单位 | 段前／段后间距、缩进支持明确的 pt、cm、mm、字符；固定值／最小值行距保留模式和 pt 值，不误识别为字号 |
| 提交条件 | 纸质版／打印版、电子版、系统上传版形成有来源的条件；条件延续至同一分支的后续属性，并读取 DOCX 章节标题中的条件 |
| 未知条件 | 保留原文和已识别的格式值；未知谓词、复杂“或”与条件组合维持待定，不生成无条件规则 |
| 范围冲突 | 同属性、范围相交、值不兼容时才构成格式冲突；明确互斥分支分开保存，未知条件的潜在交集保守待定 |
| 无冲突范围 | 从受影响规则中减去冲突交集，输出单独的类型化分片；保留未受影响的字符、章节或边距侧边 |
| 对照与报告 | 模板分组按新范围和分片对照明文；解析 Markdown 与 V1 报告展示条件、约束、冲突范围和证据 |

明确章号／表格序号表示**论文中的语义目标**，不是 Brief 文件中的段落或 XML 索引。当前解析不保证该目标已经在论文中可靠定位。

## 2. 冲突与条件示例

- “纸质版正文宋体；电子版正文黑体”：两个条件分支，没有互斥格式冲突；任务提交场景尚未确认，均为 `pending_condition`。
- “电子版正文宋体；系统上传版正文黑体”：系统上传属于电子版，二者在上传场景相交，不能当作两个互斥分支。
- “正文宋体；英文字母 Times New Roman”：在正文西文字母范围冲突。正文中文等其余字符保留 `verified` 分片；不隐含“特殊规则覆盖一般规则”的优先级。
- “正文居中；第一章正文居左”：第一章正文待定，其余章节保留无冲突分片。
- “四边页边距 2.5 cm；上边距 3 cm”：只阻断上边距，其他三个侧边保留。
- “正文小四；正文字号 12–14 pt”：单值满足区间，约束兼容。区间仍为 `check_only`，不会凭区间新增一个修改值。

普通格式值与模板观察不同也不会使模板优先。所有模板观察继续待确认，不变成学校明文要求。

## 3. 当前契约和编辑边界

当前入口输出 `AcademicParseBundle/1.5`，内含：

- `AcademicFormatRuleSet/1.4`，每条规则为 `AcademicFormatRule/1.1`；
- `AcademicSourceReview/1.1`，策略 `academic-format-scope/1.1`；
- `TemplateLayoutReport/1.1`，读取器 `docx-template-layout/1.1`，西文字母与数字观察分开。

规则新增 `semantics`：`scope.axes` 保存包含／排除集合，`constraint` 保存比较符及边界，`condition` 保存条件原文、识别状态与原因。规则集新增 `relations`、`conflicts`、`fragments`，冲突记录确切交集和确定性。缺省包含集合表示完整域，排除集合保留未列出的余集。

前置部分使用 `region_zone`，具体的摘要／目录使用 `regions`；二者可相交，不因标签不同而误判成互斥对象。是否存在实际交集仍需后续论文定位核对，解析不猜测某份论文的章节安排。

完整规则部分冲突时，整条规则不再标为 `verified`；下游可使用其独立 `verified` 分片，但必须先支持这些范围、在选定论文版本中可靠定位并验证实际修改。不能丢弃过滤条件后执行整条规则。现有正文对齐规划器会拒绝新局部选择器，防止把指定章节的要求扩大成全部正文。

Bundle 从来源证据重算规则与范围分析；规则集重算关系、冲突和分片，拒绝伪造状态或分片，规则校验约束与规范值一致。缺少字号单位、非法零字号、非有限数值和未支持的严格比较不会降级成固定编辑值。入口和重新打开任务继续从实际 Brief 重算模板报告。

历史 Bundle 1.0–1.4 保持原有读取语义和线格式。1.3 的提取器、1.0 的来源策略／审计／模板读取与分组已冻结，旧文件不会因新规则语义被重新解释。

## 4. 验证

新增语义用例覆盖条件分支与延续、章节条件、脚本／章号交集、表格／目录层级、字号区间与界限、单位歧义、未知条件、边距分片、集合减法、篡改拒绝、历史契约及资源上限。API 用例检查 V1 报告保留条件／区间／冲突位置；定位用例验证局部规则不能被旧规划器扩大。

最终回归：解析模块 **278 通过、2 跳过**；AutoFormat 集成 **43 通过、5 跳过**。41 项新增语义用例及 4 项新增集成用例通过。跳过项取决于 Linux 进程隔离或本机工具条件；来源项目的 4 项部署基线测试因部署目录未复制，按既有项目命令排除。复制快照校验：180 个文件、8 项已记录变更、0 项不匹配。

本轮只读诊断了 `E:\EasyFormat Test\1` 中 6 份 DOCX；旧 `.doc` 仍按输入范围拒绝。旧版已经提取的格式值得到保留，其中一条“正文页码居中”从旧版正文目标改为页码目标。B05 仍没有可验证的明文规则，格式线索进入来源审计；这不是格式提取已经完整的结论。

继续使用已有模板复核：材料学院模板输出 34 条明文规则、3,589 项观察；B04 输出 23 条明文规则、2,835 项观察；B05 输出 0 条明文规则、1,735 项观察。明文规则数量包含待冲突处理的条目，观察数量包含未确定值，均不表示可执行修改数量。

诊断使用 fake provider，只验证文件读取、确定性规则、范围与报告，没有调用云端模型。诊断文件位于项目忽略目录 `runtime/brief_rule_semantics_20261003/`。文件哈希检查确认原 Brief 未被修改。材料尚无用户确认标注，不据此报告准确率或召回率。

范围分析限制为 512 条类型化规则、20,000 个分析记录、每条规则 1,024 个余集分片；超限返回解析资源错误，不截掉冲突后发布规则。这些是运行限制，与论文的字数、篇幅要求无关。

## 5. 后续工作

第五项仍需实现用户决策记录、场景确认、冲突选择、模板类别确认和新规则快照编译。当前可读的提交条件不会自行绑定到任务，更不自动决定用户提交的是纸质版还是电子版。

复杂布尔条件、相对位置（如“本章”“某图之后”）、未支持句式和完整视觉区域还需继续扩展；不明确的对象或单位会报告待定。真实 Brief 的人工标注评测尚未完成。字数、词数、页数、数量和具体内容要求继续排除。

更广的论文定位与编辑属于后续模块。当前 V1 发布器仍生成原稿副本并说明未修改格式，本次完成的是解析侧语义及其交接边界。

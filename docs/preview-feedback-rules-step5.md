# 预览与用户编辑第五步：规则冲突、局部例外和有效规则快照

> 后续进度：实际编辑、跨版本继承复核、执行恢复及新版本发布已在[第六步](preview-feedback-editing-step6.md)接入；本页保留第五步当时的契约和边界。

本步将第四步的类型化候选与所选版本的学术依据、先前已核对反馈比较，保存独立的反馈规则快照。界面可以核对冲突并记录决定；本步不修改 DOCX、不重新渲染预览，也不生成论文新版本。

## 实际范围与冲突

- 只有实际对象、同一属性及字符区间相交，而且格式值不能同时满足时，才产生冲突。复用既有单位兼容判断；`25 mm` 与 `2.5 cm` 不冲突。四边页边距分别与上、下、左、右属性比较。
- 字体规则按编辑器一致的字符分类及 UTF-16 区间切分；段落、表格和分节属性保留整个最小作用单位。学术规则的已验证余集继续保留，未知条件、过滤维度、不可靠目标和仅可报告的规则不能被忽略后执行。
- 段落提升、同类及全文范围先由第四步确认，才显示可决定的冲突。本处例外只能用于已核对的选区／段落；规则更新只能用于已明确确认的同类／全文范围，局部按钮不能扩大范围。
- 保留原规则只排除相交处的新候选；本处例外或规则更新只排除明确选择的旧规则相交部分。其他属性、字符和对象余集保留。未决相交分片标记 `pending_conflict`，没有较新或局部规则默认优先的策略。
- 已核对反馈会相互比较。后续全局规则与现有局部例外冲突时，须再次展示该例外并取得决定，不能静默吞掉例外。

编译器保留来源规则、原话、Brief 证据、实际区间、被替代片段及决定引用。本地资源上限为每版 64 条核对反馈、256 次修订、20,000 个片段；超限明确要求拆分，不截断后宣布就绪。

## 契约与来源重放

新增 `FeedbackRuleSnapshot/1.1`、`FeedbackRulesReview/1.0` 和 `FeedbackDecisionRequest/1.1`；原 1.0 契约保持原状。快照包含学术依据标识、反馈分析输入、决定原请求及身份、父版本快照引用、上一修订、编译器指纹和内容哈希。

`feedback_rules_events`、`feedback_rules_snapshots`、`feedback_rules_heads` 按任务和基础版本存储追加事件、不可变快照和当前核对头。只有显式核对的反馈进入快照，不隐式纳入所有未处理反馈。分析改变时重查已纳入输入和决定，不再匹配的决定列入 `invalidated_decision_ids`。

读取不只校验 JSON 哈希：服务端重读学术来源、DOCX／PDF、原反馈、目标选择和补充决定的历史前缀，逐次重放快照链。历史快照重放确认前的原分析，不套用后来补充的值、范围或目标。重新计算校验和也不能让伪造规则或改写的审计答案成为有效来源。

冲突决定绑定任务、论文版本、DOCX、上下文、反馈、解析结果、冲突和期望快照。新决定要求当前工作版本；相同请求 ID 的确切重试，包括跨实例并发，只追加一次。不同内容复用 ID、过期快照或并发相反决定被拒绝。原反馈、Brief、旧决定和论文文件均不覆盖。

## 接口和界面

| 接口 | 作用 |
| --- | --- |
| `GET .../feedback/{feedback}/rules` | 核对反馈，返回冲突和快照；可追加来源派生的核对事件，不追加用户决定 |
| `POST .../feedback/{feedback}/rules/decide` | 记录保留／本处例外／已确认范围更新，生成新修订 |
| `GET .../feedback-rules/{snapshot_id}` | 来源重放指定历史快照 |

接口沿用本地会话、同源和版本校验，没有客户端上传规则、注册依据或提供对象路径的入口。默认适配器读取所选版本的学术决定快照；独立预览主机也可从已保存的 Intake Bundle 重放，不启动模型服务。找不到来源时保持 `pending_basis`，不能把报告文字当规则或假定规则集为空。内部测试夹具可提供明确的可信依据适配器。

已解析需求下可点击“核对规则冲突”，查看旧值、新值、原话和证据、相交对象／文字范围数量及合法选择。范围未确认时先提示范围核对，历史版本只能查看。保存期间禁用版本切换和提交，丢失响应保留同一选择及请求 ID。冲突卡片支持桌面和窄屏，文字通过 `textContent` 输出。

## 版本引用和后续边界

反馈发布引用使用独立 `FeedbackVersionReferences` 和 `VersionNode/1.1`；普通及历史节点继续使用原 `VersionNode/1.0`，原严格契约不增加字段。发布事务核验反馈快照属于选定父版本、来源标识一致、仍为预期核对头且已经就绪。引用只是依据绑定，不能替代编辑器的来源重放、计划校验及实际 DOCX 验证。

未发布的父版本核对头不会自动继承到后代或其他分支。明确发布的反馈快照通过版本引用继承，旧锚点与例外来源保留；当前子 DOCX 的目标未经重算时标记 `pending_target`，不能把旧 PDF 选区直接应用到新 DOCX。下一步完成锚点重算、经验证的执行投影和编辑适配，再生成新 DOCX、报告和预览；含待确认片段的快照不能绕过现有发布检查。

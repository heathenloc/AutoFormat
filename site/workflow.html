技术设计与产品 workflow

稳定交付可重复，无幻觉的成果

AutoFormat 将要求解析、格式编辑、预览与微调连接成一条处理链路。AI 理解要求，确定性程序执行修改，证据与版本贯穿每一步。

模块详情
01 / BRIEF PARSING

要求解析

稳定、高效、可复用的 Brief Parsing。

JSON Schema · Evidence · Domain Pack

原文约束，降低幻觉

区分明文要求、模板观察与示例。每条候选关联真实原文证据，缺失或无依据的信息保留为待确认项。

Schema 与语义双层校验

用 JSON Schema 约束输出结构，再核对对象、属性、值、单位、条件与范围，让规则可以交给程序处理。

分阶段处理，控制成本

要求提取、覆盖审计与争议分析分别承担职责。设置超时、有限重试与 Token 预算，复用已验证的解析结果。

版本化接口，方便复用

固定模型与 Prompt 版本，通过解析 Bundle、领域包和模型适配器接入不同宿主，保持清晰的输入、输出与验证边界。

原文证据 · E-001
“正文采用宋体。”

候选值需要得到原文支持，模板观察保留独立来源。

结构化输出 · 简化示意
{
        "object": "body",
        "attribute": "font",
        "value": "宋体",
        "evidence": "E-001"
      }

有疑问先确认，在修改前做决定。

交互示意

正文存在两种字体要求，本次采用哪一条？

要求 A：正文使用宋体。要求 B：正文使用黑体。
选择字体要求或暂时忽略

请选择一个选项。未回答时，格式编辑保持等待。

可靠明文规则无需逐条询问。暂时忽略不会成为默认规则，相关项目仍保留在报告中。

02 / DOCUMENT ENGINE

格式编辑

确定性执行，逐项验证。

C# / .NET · Open XML SDK

经过验证的规则才执行

将类型化规则转换为对象定位与修改计划，按指定属性和作用范围执行，保留论文语义、表格数据与引用内容。

每次修改都有独立版本

原稿 V0 与已发布历史保持不变。每轮从选定父版本创建新文件，规则快照与本次编辑绑定，防止改答后发布过期结果。

保存后重新读取和验证

重新检查实际格式属性、文档结构与文字内容，记录修改位置、依据和验证结果，让每次操作可以追溯。

明确执行边界，减少返工

将规则理解与文档执行分开。定位不可靠、条件不明确或存在冲突时先确认，再提交可靠的修改计划。

  1. 定位对象
  2. 生成计划
  3. 编辑副本
  4. 回读验证
03 / PREVIEW & REFINE

预览与微调

看见结果，调整细节。

TypeScript · PDF.js · LibreOffice

预览、报告与版本一起交付

通过 LibreOffice 生成 PDF，使用 PDF.js 浏览、缩放与选择文字。结合报告查看修改依据，并下载可继续编辑的 DOCX。

选中哪里，就从哪里微调

选中文字并提出需求，明确实际作用范围。段落属性会显示所在段落；扩大范围、定位不唯一或冲突时先确认。

轻量解析，复用已有结果

局部反馈复用格式规则与校验能力，结合已验证的解析结果和决定快照，减少重复处理整份要求的模型调用。

持续微调，历史可追溯

每轮微调生成独立的新文档、报告与预览。用户可以查看历史，选择任一版本作为后续修改的起点。

选区与需求 → 轻量解析与范围核对 → 必要确认 → 格式编辑 → 新版本预览
